# Shell: dark first paint, navbar and legal footer

## Code path

1. `src/styles/tokens.ts` exports `shellBackground`, the page background color.
2. `src/app/layout.tsx` puts it inline on `<html>` (`style={{ backgroundColor, colorScheme: "dark" }}`). It also exports `viewport` with `colorScheme: "dark"` and `themeColor`, which Next.js renders as `<meta name="color-scheme">` and `<meta name="theme-color">`.
3. `src/styles/globals.css` defines the same value as the `--background` token (shadcn's name, ADR 0009), used by the `bg-background` class on `<body>`. `<html>` also carries the `dark` class, because the site is dark only and shadcn's components style their dark look through it.
4. `src/styles/shell-background.test.ts` reads `globals.css` and fails if `--background` and `shellBackground` differ, or if any value in `palette` (used by canvas and WebGL effects) differs from its CSS token.
5. `src/components/site-footer.tsx` renders the footer line in T7SEN's words and the NEXON Open API attribution (`SKILL.md` section 7) inside `<footer>`, which the root layout puts on every page, including the 404 page.
6. `src/components/site-header.tsx` puts the navbar in a sticky `<header>` that ignores clicks (`pointer-events-none`); only the nav takes them (`pointer-events-auto`), so the page around and under the floating pills stays usable. PillNav uses its split layout: the logo mark in a round pill and the links are two glass pills. The header's height is the `--site-header-height` token (3.5rem: a 0.75rem gap above the 44px navbar). The home hero (`src/app/page.tsx`) and the chat page's hero (`src/app/tools/chat/page.tsx`) pull themselves up by that much (`-mt-(--site-header-height)`) and add it back to their top padding, so the dot grid and glow (`src/components/hero-backdrop.tsx`, shared) reach the top of the page behind the navbar while the heroes' content stays put. Pages without a hero start below the header.
7. `src/components/site-nav.tsx`, a client component, passes `sitePages` from `src/data/site-pages.ts` to PillNav (`src/components/react-bits/pill-nav.tsx`) and marks the link whose `href` equals `usePathname()`. The root layout keeps it mounted across client navigations, so the current-page dot slides to its new link instead of the bar reloading.
8. `src/data/site-pages.test.ts` walks `src/app` for `page.*` files, turns each folder path into its URL (route groups such as `(marketing)` add no segment; `_private` folders and `@slot` folders are skipped) and fails unless the URLs equal the `href`s in `sitePages` (ADR 0010).
9. `src/components/logo-mark.tsx` holds the logo: `logoPath`, one stroked path on a 128 grid, and `LogoMark`, which draws it in the current text color, cropped to the mark (viewBox `16 21 96 86`) and `aria-hidden`. `site-nav.tsx` passes it alone to PillNav with the link label "ArcheLab"; `site-footer.tsx` puts it before the word ArcheLab. Both color it `text-primary`. `src/app/icon.svg` is the favicon: Next.js serves it statically and links it from every page's `<head>` (ADR 0019). `logo-mark.test.ts` checks that the favicon draws `logoPath` at `logoStrokeWidth`, in `palette.primary` on `palette.background`.
10. The legal pages (`src/app/legal`, `src/app/privacy`, `src/app/terms`, ADR 0021) render `LegalPage` from `src/components/legal-page.tsx` with facts from `src/data/legal.ts`. `legalPages` in `site-pages.ts` lists them; `site-footer.tsx` links them in its Legal column, and `site-pages.test.ts` reads `allPages`, so a legal page counts as listed without a navbar link.
11. `tests/e2e/shell.spec.ts` checks the footer text on `/`, `/tools/chat` and a missing page; on each listed page, that the navbar links every page and marks only that one with `aria-current="page"`; that the navbar's logo links home, turns once on hover and stays still under reduced motion (it reads the mark's running animations); and, at 260px, that the links fold into a menu that opens, closes with Escape (focus returns to the button), navigates, and also closes with reduced motion.

## Why it is shaped this way

- The stylesheet is a separate file. Until it arrives, the browser paints its default canvas, which is white in a light-mode browser. The inline style is part of the HTML itself, so the dark background applies at first paint. In the built HTML, `<html style="background-color:…">` comes before the stylesheet `<link>`.
- `color-scheme: dark` also makes form controls and scrollbars dark before CSS loads.
- The background value has to exist twice: once in TypeScript for the inline style and once in CSS for Tailwind. The unit test makes the duplication safe.
- Next.js cannot list an app's pages at run time, and reading a label exported from each page file would mean importing every page into the navbar's client bundle, so the navbar keeps its own list. The unit test is what makes a new page join the navbar without anyone remembering to.
- PillNav decides between links and a menu by measuring: the hidden copy of the links (`measureListRef`) plus the logo's width (`logoRef`) against the header's inner width. The original assumed a round logo of fixed size; this copy measures the real element, which the wordmark needed and the round logo pill still passes. With today's two links the navbar folds at 278px wide and below (346px with the old wordmark), so phones from 320px up keep the links.
- **The logo's spin is React Bits' own.** The adapted copy first dropped it along with the round pill; T7SEN asked for it back (ADR 0019). `spin` runs on `pointerenter` of the logo link and animates the mark's span (`markRef`) with the Web Animations API: one 360-degree turn over 900ms. It returns early for touch pointers (a tap would spin and navigate at once), while a turn is still running (`getAnimations()`), and under reduced motion. The intro's pop animates the outer `logoRef` span, so the two never fight over one element's transform.
- The favicon is a plain SVG file, not code: an `icon.svg` cannot read CSS variables or import `logoPath`, so the test is what keeps it in step with the logo and the tokens. The tile behind the mark keeps it readable on light and dark tab strips.

- **The home page reads NEXON once per set and hides what fails.** `page.tsx` awaits `fetchShowcase` while it is prerendered: `descendant.json` and `weapon.json`, each through `fetchMetadataSet`, which checks entries one by one and returns none on any failure (ADR 0018). The Descendants' portraits also feed the chat builder's sample window, so the page fetches `descendant.json` once. `GameShowcase` leaves out a carousel with no items.
- **A carousel page is whole cards.** `CardCarousel`'s track is a CSS grid row (`.card-carousel-track`) that scrolls and snaps to card starts, with column widths per breakpoint. `geometry` measures the first card's width plus the 16px gap, fits as many whole cards as the track shows (4, 2 or 1), and calls that a page: `scrollBy` moves exactly one page, the counter is `ceil(cards / perPage)`, and a track scrolled to its end always reads as the last page, even when that page holds fewer cards. Measuring the track's width alone gave 1/30 on phones, where cards are 80% wide. The page follows `scroll` and a `ResizeObserver`, so swipes and rotation count. Hover and focus are separate holds, so moving the pointer out does not restart rotation while focus is still inside. Reduced motion comes from `useSyncExternalStore` with a server snapshot of false, so hydration never mismatches.
- **Descendant links are share links.** Each card's link is `/tools/chat` plus `shareHash` of `<img id="…"/>` markup (ADR 0015). The id comes from the chat registry: a base Descendant's `descendant` art (`Icon<Name>1`), or an Ultimate's `ticket` art (`Icon_CharacterTicket_NNN_U01`).

## What would break it

- Changing `--background` without changing `shellBackground`, or the reverse. The unit test catches this.
- Removing the `dark` class from `<html>`. shadcn components fall back to their light styling for inputs and toggles.
- Removing the inline style from `<html>`. Nothing fails, but the white flash returns. Check the built HTML: `.next/server/app/index.html` should start with the styled `<html>` tag.
- Moving the footer out of the root layout, or into a client-only component. The e2e test catches a missing footer.
- Editing the legal text in one place only. It must match `SKILL.md` section 7 exactly, and the e2e test checks the published wording.
- Adding a page without an entry in `src/data/site-pages.ts` (`sitePages` for the navbar, `legalPages` for the footer), or renaming a route folder without updating its `href`. The unit test catches both.
- Changing the navbar's size (PillNav `size`) or the header's top gap without updating `--site-header-height`. The header would clip or pad the pills, and the hero would no longer line up with the top of the page.
- Changing `logoPath` without `src/app/icon.svg`, or `palette.primary` or `palette.background` without the favicon's hex values. The unit test catches both.
- Putting text beside the navbar's logo, or making it wider. The links fold into the menu sooner; the e2e menu tests use 260px and need the fold above it.
- Moving the spin onto `logoRef`'s span: its intro pop animates `transform` there too.
- Removing `pointer-events-auto` from the nav: the header's `pointer-events-none` would make the navbar unclickable. The e2e menu test catches it.
- Adding a dynamic route (`[slug]`). The test would list it with its brackets; decide how the navbar treats it first (ADR 0010).
