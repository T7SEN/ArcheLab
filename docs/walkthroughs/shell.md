# Shell: dark first paint, navbar and legal footer

## Code path

1. `src/styles/tokens.ts` exports `shellBackground`, the page background color.
2. `src/app/layout.tsx` puts it inline on `<html>` (`style={{ backgroundColor, colorScheme: "dark" }}`). It also exports `viewport` with `colorScheme: "dark"` and `themeColor`, which Next.js renders as `<meta name="color-scheme">` and `<meta name="theme-color">`.
3. `src/styles/globals.css` defines the same value as the `--background` token (shadcn's name, ADR 0009), used by the `bg-background` class on `<body>`. `<html>` also carries the `dark` class, because the site is dark only and shadcn's components style their dark look through it.
4. `src/styles/shell-background.test.ts` reads `globals.css` and fails if `--background` and `shellBackground` differ, or if any value in `palette` (used by canvas and WebGL effects) differs from its CSS token.
5. `src/components/site-footer.tsx` renders the footer line in T7SEN's words and the NEXON Open API attribution (`SKILL.md` section 7) inside `<footer>`, which the root layout puts on every page, including the 404 page. Beside ArcheLab's name, "Version" and the Changelog's newest version (`changelog[0]`, the same as `package.json`'s) link the Changelog (T7SEN, 2026-10-19). The attribution's "NEXON Open API" is a link to NEXON's API site, split out of `attributionText` so the line's text stays word for word. Its columns: Tools (the live tools from the registry, then `footerToolHrefs`: the database page, then the coming tools), Database (`footerDatabaseHrefs`: Descendants, Weapons, Modules), Community (`footerCommunityHrefs`: Help fill in data) and Legal.
6. `src/components/site-header.tsx` puts the navbar in a sticky `<header>` that ignores clicks (`pointer-events-none`); only the nav takes them (`pointer-events-auto`), so the page around and under the floating pills stays usable. PillNav uses its split layout: the logo mark in a round pill and the links are two glass pills. The header's height is the `--site-header-height` token (3.5rem: a 0.75rem gap above the 44px navbar). The home hero (`src/app/page.tsx`) and the chat page's hero (`src/app/tools/chat/page.tsx`) pull themselves up by that much (`-mt-(--site-header-height)`) and add it back to their top padding, so the dot grid and glow (`src/components/hero-backdrop.tsx`, shared) reach the top of the page behind the navbar while the heroes' content stays put. Pages without a hero start below the header.
7. `src/components/site-nav.tsx`, a client component, turns `navbarEntries()` from `src/data/site-pages.ts` into PillNav items (`src/components/react-bits/pill-nav.tsx`) and marks the link whose `href` equals `usePathname()`. The root layout keeps it mounted across client navigations, so the current-page dot slides to its new link instead of the bar reloading. A page's own link gets its `href` and `label` only: its `icon` is for the footer, and PillNav would draw it in the pill. The database pages share one Database item (`group: "Database"`, ADR 0027), a link to the database page whose menu, opening on hover, shows the other pages' links with their icons (ADR 0034); see `docs/walkthroughs/external-components.md` for how the menu opens and closes. It also passes `foldBelow={navbarFoldBelow}`, the width below which the bar folds, kept beside `sitePages` (ADR 0010).
8. `src/data/site-pages.test.ts` walks `src/app` for `page.*` files, turns each folder path into its URL (route groups such as `(marketing)` add no segment; `_private` folders and `@slot` folders are skipped) and fails unless the URLs equal the `href`s in `sitePages` (ADR 0010).
9. `src/components/logo-mark.tsx` holds the logo: `logoPath`, one stroked path on a 128 grid, and `LogoMark`, which draws it in the current text color, cropped to the mark (viewBox `16 21 96 86`) and `aria-hidden`. `site-nav.tsx` passes it alone to PillNav with the link label "ArcheLab"; `site-footer.tsx` puts it before the word ArcheLab. Both color it `text-primary`. `src/app/icon.svg` is the favicon: Next.js serves it statically and links it from every page's `<head>` (ADR 0019). `logo-mark.test.ts` checks that the favicon draws `logoPath` at `logoStrokeWidth`, in `palette.primary` on `palette.background`.
10. The legal pages (`src/app/legal`, `src/app/privacy`, `src/app/terms`, ADR 0021) render `LegalPage` from `src/components/legal-page.tsx` with facts from `src/data/legal.ts`. `legalPages` in `site-pages.ts` lists them; `site-footer.tsx` links them in its Legal column, and `site-pages.test.ts` reads `allPages`, so a legal page counts as listed without a navbar link.
11. `tests/e2e/shell.spec.ts` checks the footer text and its version link to the Changelog on `/`, `/tools/chat` and a missing page; on each listed page, that the navbar links every page, the database pages once its Database menu opens on hover, and marks only that one with `aria-current="page"`, and the Database item `aria-current="page"` on the database page and `"true"` when the page is one of its links; on a Descendant's page, that Database and Descendants are marked `aria-current="true"`, in the bar's menu and in the folded menu, where the Equipment section starts open; that the Database menu opens on hover and stays open while the pointer crosses into it, closes when the pointer leaves, with Escape (focus goes to the item), a press outside, Tab past its last link (column by column), and a link, opens on Tab onto the item, and that a click on the item opens the database page; that the menu gives each section a column, each a heading over its pages, and at 600 by 520px puts the sections after Equipment in one column, stays on the screen and scrolls to its last page (ADR 0051); that the navbar's logo links home, turns once on hover and stays still under reduced motion (it reads the mark's running animations); at 260px, that the links fold into a menu that opens, closes with Escape (focus returns to the button), navigates, lists the Database group's own page and a button per section under its label, each closed and opening and closing its links, and also closes with reduced motion; that no page scrolls sideways at 390px, with JavaScript and without it; and that the navbar's first paint matches PillNav's measured navbar: with JavaScript off and on, at 390px, one pixel either side of `navbarFoldBelow` and at 1280px, the same controls show at the same places. The menu tests first wait for `data-fold-below` to go (`measured`): the menu button now shows before hydration, and a click then would open nothing.

## Why it is shaped this way

- The stylesheet is a separate file. Until it arrives, the browser paints its default canvas, which is white in a light-mode browser. The inline style is part of the HTML itself, so the dark background applies at first paint. In the built HTML, `<html style="background-color:…">` comes before the stylesheet `<link>`.
- `color-scheme: dark` also makes form controls and scrollbars dark before CSS loads.
- The background value has to exist twice: once in TypeScript for the inline style and once in CSS for Tailwind. The unit test makes the duplication safe.
- Next.js cannot list an app's pages at run time, and reading a label exported from each page file would mean importing every page into the navbar's client bundle, so the navbar keeps its own list. The unit test is what makes a new page join the navbar without anyone remembering to.
- PillNav decides between links and a menu by measuring: the hidden copy of the links (`measureListRef`) plus the logo's width (`logoRef`) against the header's inner width. The original assumed a round logo of fixed size; this copy measures the real element, which the wordmark needed and the round logo pill still passes. PillNav's `trailing` pill, the command palette's search button, joins the measured width. With today's four links the navbar folds at 549px wide and below (452px with three links, 330px with two, 278px before the search pill, 346px with the old wordmark), so phones get the menu and tablets keep the links. The measuring copy sits in a zero-width clipped box (`MEASURE`), with the copy itself at `w-max`; the ResizeObserver watches the copy, since the box's own size never changes. Without the clip, the hidden copy widened every page past a phone's edge (ADR 0024).
- **The first paint folds by CSS.** PillNav can only measure in the browser, after hydration, so its server HTML used to show the links, 478px wide on a 390px phone until the script ran. Now `collapsed` starts as `null` (unmeasured) when the nav gets `foldBelow`: the server's HTML and the client's first render hold both the bar and the menu button, the nav carries `data-fold-below`, and a `<style>` from `foldCss` picks one by screen width. Below `foldBelow` it hides the bar (`data-part="bar"`) and gives the nav its folded layout; from it up it hides the menu button (`data-part="toggle"`). The first layout effect measures, `collapsed` becomes true or false, and the attribute and the `<style>` go, so the measured fold rules from then on. The rules are unlayered, so they win over Tailwind's utilities without `!important`. The engine (glide and dot) and the intro wait for the measured value: they run once, on the settled layout, as before. `navbarFoldBelow` is a viewport width, as the fold widths in ADR 0010 are; PillNav measures the header's inner width, which on a desktop with classic scrollbars is a scrollbar narrower, so within that band a desktop window can still switch once at hydration. Phones have overlay scrollbars. Without JavaScript the menu button opens nothing; the footer links every page.
- **The logo's spin is React Bits' own.** The adapted copy first dropped it along with the round pill; T7SEN asked for it back (ADR 0019). `spin` runs on `pointerenter` of the logo link and animates the mark's span (`markRef`) with the Web Animations API: one 360-degree turn over 900ms. It returns early for touch pointers (a tap would spin and navigate at once), while a turn is still running (`getAnimations()`), and under reduced motion. The intro's pop animates the outer `logoRef` span, so the two never fight over one element's transform.
- The favicon is a plain SVG file, not code: an `icon.svg` cannot read CSS variables or import `logoPath`, so the test is what keeps it in step with the logo and the tokens. The tile behind the mark keeps it readable on light and dark tab strips.

- **The home page reads NEXON once per set and hides what fails.** `page.tsx` awaits `fetchShowcase` while it is prerendered: `descendant.json` and `weapon.json`, each through `fetchMetadataSet`, which checks entries one by one and returns none on any failure (ADR 0018). The Descendants' portraits also feed the chat builder's sample window, so the page fetches `descendant.json` once. `GameShowcase` leaves out a carousel with no items.
- **A carousel page is whole cards.** `CardCarousel`'s track is a CSS grid row (`.card-carousel-track`) that scrolls and snaps to card starts, with column widths per breakpoint. `geometry` measures the first card's width plus the 16px gap, fits as many whole cards as the track shows (4, 2 or 1), and calls that a page: `scrollBy` moves exactly one page, the counter is `ceil(cards / perPage)`, and a track scrolled to its end always reads as the last page, even when that page holds fewer cards. Measuring the track's width alone gave 1/30 on phones, where cards are 80% wide. The page follows `scroll` and a `ResizeObserver`, so swipes and rotation count. Hover and focus are separate holds, so moving the pointer out does not restart rotation while focus is still inside. Reduced motion comes from `useSyncExternalStore` with a server snapshot of false, so hydration never mismatches.
- **Descendant cards open their page.** Each card links to `/descendants/<slug>` (ADR 0023), named by its visible text, name then badge ("Hailey Ultimate"). The carousel header's "All Descendants" link sits in `CardCarousel`'s `action` slot, before the buttons. The share link to the builder with a Descendant's icon moved to that Descendant's page.
- **The tool card's button keeps its WebGL context across effect re-runs.** `SpecularButton` (`src/components/react-bits/specular-button.tsx`) draws its rim and shine on a WebGL2 canvas. React Bits' original cleanup called `WEBGL_lose_context.loseContext()`. Strict Mode under `pnpm dev` runs that cleanup and then the effect again on the same canvas, and `getContext` hands back the same, now lost, context: shaders fail to compile and Chromium paints the lost canvas as a white box with a broken-image icon (found 2026-10-17, with or without reduced motion). The cleanup now deletes the program and buffers but loses the context only when the canvas has left the page (`!canvas.isConnected`), which is true on a real unmount, as passive cleanups run after the DOM is removed. A context lost any other way (a GPU reset, too many contexts) hides the canvas, at mount or on `webglcontextlost`, so the button falls back to its CSS tint and shadow; the context is not restored.

## What would break it

- Changing `--background` without changing `shellBackground`, or the reverse. The unit test catches this.
- Removing the `dark` class from `<html>`. shadcn components fall back to their light styling for inputs and toggles.
- Removing the inline style from `<html>`. Nothing fails, but the white flash returns. Check the built HTML: `.next/server/app/index.html` should start with the styled `<html>` tag.
- Moving the footer out of the root layout, or into a client-only component. The e2e test catches a missing footer.
- Editing the legal text in one place only. It must match `SKILL.md` section 7 exactly, and the e2e test checks the published wording.
- Adding a page without an entry in `src/data/site-pages.ts` (`sitePages` for the navbar, `legalPages` for the footer), or renaming a route folder without updating its `href`. The unit test catches both.
- Changing the navbar's size (PillNav `size`) or the header's top gap without updating `--site-header-height`. The header would clip or pad the pills, and the hero would no longer line up with the top of the page.
- Changing `logoPath` without `src/app/icon.svg`, or `palette.primary` or `palette.background` without the favicon's hex values. The unit test catches both.
- Putting text beside the navbar's logo, or making it wider. The links fold into the menu sooner; the e2e menu tests use 260px and need the fold above it.
- Giving a heavy page a navbar entry without `prefetch: false`: Next.js prefetches every navbar and footer link on every page (the modules index's data is about 35 KB compressed; ADR 0025).
- Adding, removing or renaming a navbar page, or changing the pills' sizes or font, without measuring the fold again and updating `navbarFoldBelow`. The first paint would fold at the old width and switch at hydration. The e2e first-paint test fails.
- Changing the folded layout (ROOT's or the trailing pill's `data-[collapsed]` classes) without `foldCss`, which repeats it for the first paint. The e2e first-paint test compares the two.
- Rendering the toggle only when `collapsed` is true, or dropping the `<style>`: phones get the unfolded links until hydration again. The e2e 390px test without JavaScript fails.
- Moving the spin onto `logoRef`'s span: its intro pop animates `transform` there too.
- Removing `pointer-events-auto` from the nav: the header's `pointer-events-none` would make the navbar unclickable. The e2e menu test catches it.
- Adding a dynamic route (`[slug]`). The test would list it with its brackets; decide how the navbar treats it first (ADR 0010).
- Calling `loseContext()` unconditionally in `SpecularButton`'s cleanup again, as re-adding it from the registry would: the button is a white box under `pnpm dev`. No test catches it; look at the button in dev (`SKILL.md` landmine 19).
