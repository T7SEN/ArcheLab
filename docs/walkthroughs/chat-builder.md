# Chat builder

The builder at `/tools/chat` composes one line of chat, previews it the way the game shows it, and copies markup that fits the chat limit. The UI lives in `src/features/chat/ui`. Every game fact it shows comes from `src/data/chat-tags.json` through the engine (`docs/walkthroughs/chat-engine.md`).

## Code path

The page is built from shadcn/ui components and adapted React Bits effects (ADR 0009). Its hero (`HeroBackdrop`, a ShinyText title, the in-game verified badge) sits above the builder. The message window, a SpotlightCard styled like the home page's sample window, holds the channel chips, the editor drawn as the in-game chat line (it is the preview), the folded markup panel, a usage bar, and a footer with the StarBorder Copy button, Copy link, a Clear button and the counter badge (React Bits Counter). The Style panel beside it, also a SpotlightCard, holds a search box and accordion sections for styles and icons; GlareHover sweeps the color swatches. On wide screens the message window stays in view (sticky) while the Style panel scrolls.

Three details keep it working:

- The window's inner grid is `grid-cols-1` (`minmax(0, 1fr)`). With an `auto` column, a long unbroken message set the editor's minimum width and pushed the editor and markup box past the window's edge.
- The counter rolls its digits in `aria-hidden` strips and keeps the plain number in a screen-reader span, so the editor's accessible description still reads "13 / 100 87 characters left." The e2e tests check that description instead of the visible text, which now contains the digit strips.
- GlareHover is laid over each swatch, inside the button: wrapping the button would clip its pressed and focus rings.


1. **Page.** `src/app/tools/chat/page.tsx` is a server component, prerendered as a static page. While it renders, `fetchPortraitUrls` (`src/lib/nexon/descendants.ts`, server-only) reads NEXON's `descendant.json` once and returns the base Descendant portrait URL for each portrait icon in the registry (ADR 0008). The page passes those URLs to the client component `ChatBuilder`.
2. **State.** `ChatBuilder` holds one message: the markup panel's text and the engine pieces. Everything else is derived from them on each render:
   - the copy text: the shorter of the optimizer's output and the text as written;
   - the count, with `count`;
   - what the game shows: the copy text after `truncateToLimit`, parsed;
   - the hints.
3. **Editor.** `ChatEditor` mounts ProseMirror (ADR 0007) into a `div` that React never touches.
   - `editor-schema.ts` defines one line of inline content, one `style` mark, and inline atom images.
   - `editor-model.ts` converts between editor content and pieces.
   - Every change goes up as pieces. When the pieces change from outside, the editor replaces its content, unless the content already serializes the same.
4. **Commands and plugins.** `editor-plugins.ts`:
   - `applyStyle` removes the old style and adds the new one to text only. With no selection, it sets the style for what is typed next.
   - `insertImage` inserts an unstyled image.
   - `normalizePlugin` runs after every change. It removes refused characters and line breaks, and strips any style from images.
   - `overflowPlugin` highlights what the game will not show as written.
   - The keymap blocks Enter and adds undo and redo.
5. **Markup panel.** `MarkupPanel` is a textarea over a backdrop that repeats the text with the same metrics and marks the part past the input box's cut. Panel input goes through `cleanMarkup` (line breaks become spaces, refused characters are removed), then `parse`.
6. **Picker.** `styleGroups` (`style-options.ts`) lists each look once, under the shortest of the tags that render it. Groups follow appearance, never where a tag name came from: saturated colors in hue order (hues from 345° wrap to the start, so all reds sit together), the four rarity colors, and near-neutral colors (chroma below 0.15) from light to dark. A look's group comes from its first registry entry, which only matters for `tier3`, whose same-looking `UltimateCharacter` follows it. Each option carries its cost, its contrast against the chat background, and the longer names it replaces. Picker buttons keep the editor's focus (`keepEditorFocus`), so the selection survives a click. Icons split by `isPortrait` (`icon-options.tsx`): Descendant portraits render as name tiles in their own section, A to Z; the other icons stay chips, in sections by what their ids name (`iconGroups`, `iconGroupOf`: the four currency ids `cash`, `BlueCash`, `RedCash` and `Gold`, first so the section sits right below Descendants; other `Icon<Name><n>` portrait ids, which have no API portrait; `Mission…`, `Boss_…`, `Quest…`, the two boss icons, `TargetMission` and `SubVulgusPost`; `Npc…`; a fixed set of damage types; `Mouse…` and `GamePad…`; both ticket spellings, `Icon_CharacterTicket_…` and the older `Icon_CharacterTicket01`; everything else in Other, including `Qulipothium` and `DimensionalFragment`, whose ids do not name a currency). The ids are the only guide, since most icons' appearance is not described; a new id that fits no rule lands in Other, and `icon-groups.test.ts` pins every current id to its section. `byLabel` sorts each section A to Z with numeric order ("Mission 2" before "Mission 10"). `isUntested` (an image with `source: "community"`) adds the "?" mark, the tooltip line and the accessible-name suffix, and `ChatBuilder`'s `untestedIcons` turns any such icon in the message into a hint (ADR 0011).
7. **No separate preview.** The editor is the in-game view: the channel's untagged color, game colors and a stand-in "You:" sender, on the site's dark surface. The Game background switch (`gameBackground` state in `ChatBuilder`, a shadcn Switch) puts the sampled chat panel `#212321` behind it instead; the box carries `data-game-background` while it is on, which the e2e test reads. Contrast hints measure against `#212321` either way, so a warning means the same thing whichever background is shown. The overflow highlight marks what the game cuts. `ChatLine` (`chat-line.tsx`) still draws read-only lines: `ChatShowcase` (`chat-showcase.tsx`) uses it for the home page window of sample messages. It draws the parsed message on the sampled chat background, with untagged text in the chosen channel's color. Sizes scale by their measured cap heights against untagged text. `ChatIcon` shows the art from `artUrlOf` (`chat-icons.ts`): the Descendant's API portrait, or for `nexon-site` art the image on NEXON's CDN (ADR 0012). It shows the labeled placeholder when there is no art or the image fails to load.

## Why it is shaped this way

- **Pieces are the only source of truth.** The editor and the panel both write pieces, and everything else reads them. Two-way sync then never compares DOM or strings ad hoc (`SKILL.md` landmine 10). It goes through `parse` and `serialize`.
- **One style per run is enforced at two levels.** ProseMirror marks of one type exclude each other, so a run cannot hold two styles. `addMark` would still style an image (the test "lets addMark style an image" pins this), so `applyStyle` styles text nodes only and `normalizePlugin` strips styles from images that arrive by paste.
- **The editor takes a non-empty browser selection on blur, too.** Tabbing from the editor through the style search moves the browser's selection into that text field, so the editor captures the selection while it still has it (`handleDOMEvents.blur`). It never takes a collapsed browser selection: after Ctrl+A over styled text, ProseMirror holds the whole line while the browser reports a caret.
- **Pickers read the visible selection first.** ProseMirror reads native selection changes only while it has focus. A keyboard user who selects with Shift+Home and tabs straight to a picker button can blur the editor before that read happens, and the style would land on the old cursor. `syncSelectionFromDom` maps the browser's selection back with `posAtDOM` before each picker command. The e2e test "a style can be applied with the keyboard alone" failed without it.
- **Normalization is a plugin, not input handlers.** Typing, paste, drop and composed input (IME) all reach the document through transactions. Checking the result after each change catches refused characters whatever their route.
- **The copy text is the shorter one.** The optimizer escapes every `<` that could start a tag. Typed text such as an unclosed `<cash>` already shows literally, so what was written can be shorter than the optimizer's output, and both render the same.
- **The overflow highlight compares renderings.** The input box cuts markup, not text. Cutting inside a closing tag leaves the whole run unclosed and shown as typed (T4). The editor therefore highlights from the first glyph where the cut message renders differently from the full one, not from a character count.
- **Icon size is in cap heights.** T7SEN's P15 screenshot shows 26px icons beside 12px capitals, ending 3.5px below the baseline. In the editor and chat lines, `globals.css` makes `.chat-icon` `calc(26 / 12 * 1cap)` tall and gives art icons `vertical-align: calc(-3.5 / 12 * 1cap)`. An image's baseline is its bottom edge, so that drops it below the text baseline, as in game. Placeholders keep `middle`, because their baseline is their label's. Descendant portraits are bigger and round in game (Q1: a 46px disc beside 12px capitals, 5px below the baseline), so `chatIconClass` adds `chat-icon-portrait` to icons with `descendant` art, and that class gives them `calc(46 / 12 * 1cap)`, `vertical-align: calc(-5 / 12 * 1cap)`, a round crop, a dark fill and a light ring: the API portrait is transparent around the Descendant, so a crop alone would not show the disc. Character tickets (`ticket` art, ADR 0014) also get `chat-icon-ticket`, which turns the ring gold (`--ticket-ring`); `artUrlOf` looks their Descendant up in the same portrait map, which the chat page fills from both art kinds. The rules require `:has(> img)`, so a portrait that fails to load falls back to an ordinary placeholder. The pickers keep 2em, so chips and tiles keep their size. The e2e test divides the icon's height by a `1cap` probe in the same font. It copies the font longhands, because Chrome reports the `font` shorthand empty there.
- **Clear is an editor edit.** `ChatEditorHandle.clear` deletes the whole document in an ordinary transaction, so undo restores it, and wraps it in `closeHistory` so it is its own undo step: ProseMirror's history otherwise merges an edit made within 500ms of typing into the typing's step. `ChatBuilder` also resets the message itself, because markup that renders as nothing (such as `<red></>`) leaves the editor empty already, and an empty delete changes nothing.

- **Share links live in the hash and are used up.** `share-link.ts` builds and reads `#m=<code>&c=<channel>` (ADR 0015). `ChatBuilder` opens a link in an effect, after hydration, and on `hashchange`; the server never sees the hash, so the page stays static. Opening loads the markup the way the markup panel does (`cleanMarkup`, then `parse`), and the editor syncs through its `pieces` prop as an external change, so the "Opened a shared message." notice survives until the first edit. The hash is then removed, so a reload keeps later edits. `Notice` has a tone: removed characters and broken links warn, the rest informs. `CopyStatus` names its target, so only the button that copied says so.
- **Personal templates live in this browser, and loading one is an edit.** `TemplatesSheet` reads `localStorage` once, in a lazy `useState` initializer: the sheet's content mounts only when it opens, so the server render never needs storage and hydration cannot mismatch, and no effect sets state on mount. A `storage` listener follows other tabs. Every write goes through `storeTemplates`, which reports a refusal instead of throwing. Stored text is untrusted, so `pickTemplate` runs it through `cleanMarkup` and accepts only a channel the registry knows (ADR 0017). `pickTemplate` calls `ChatEditorHandle.replace`, one `closeHistory` transaction, so undo restores the old message; it sets the notice after that call, because the editor's change clears notices synchronously and the later state update wins. The sheet is controlled (`templatesOpen`), and its `finalFocus` hands focus to `ChatEditorHandle.element()` after a pick: otherwise Base UI returns it to the Templates button.
- **E2e tests wait for hydration.** The server-rendered buttons are clickable before React attaches its handlers, and such a click is lost; under the load of three browsers that made tests time out. `beforeEach` waits for the editor, which mounts with the page's effects. The share tests replace `navigator.clipboard.writeText` with a recorder, because Firefox and WebKit do not let a test read the clipboard.

## What would break it

- **A registry change without an engine change.** New fields need the Zod schema in `registry.ts`. New rules fail `createRegistry` on purpose.
- **Removing `normalizePlugin`.** Pasted emoji would reach the copy text, and styled images could appear. The unit tests in `editor-plugins.test.ts` and the e2e test for refused characters fail.
- **Letting React render inside the editor's mount point.** ProseMirror owns that DOM, so React would fight it.
- **Changing the markup panel's or backdrop's font, padding or wrapping on one side only.** The overflow highlight stops lining up with the text.
- **A NEXON outage at build time.** The page still builds, and every icon shows its placeholder. The weekly scheduled deploy tries again.
